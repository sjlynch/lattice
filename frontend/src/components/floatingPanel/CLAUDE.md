# frontend/src/components/floatingPanel

- `geometry.ts` owns viewport padding, position clamping, initial placement, and the persisted `{ pos, size }` localStorage shape.
- `FloatingPanel` / `useFloatingPanelState` accept optional `defaultPosition` for first-open placement (Security uses the right edge). Saved geometry takes precedence, and placement is still clamped to the viewport.
- `hooks.ts` is a re-export barrel only (`useFloatingPanelState`, `panelForEscape`, `useFloatingPanelEscape`, `usePanelDrag`, `usePanelResize`); `../FloatingPanel.tsx` and tests import from it, so new hooks go in the concern modules below and are re-exported here. `../FloatingPanel.tsx` should stay focused on portal markup and wiring.
- `usePanelGeometry.ts` — `useFloatingPanelState`: `pos`/`size` state seeded from storage, the open-clamp, the `maximized`/`toggleMaximize` toggle, and persistence. Writes are **coalesced** through `createGeometryWriteQueue`: drag/resize change geometry on every mousemove, so each key's latest `{ pos, size }` is written at most once per animation frame, and flushed synchronously on unmount, on `pagehide`, and before a mounting panel reads its key — the stored value always ends where a write per change would have left it. Pinned by `__tests__/floatingPanelGeometryWrites.test.ts`.
- `panelEscapeStack.ts` — the module-level open-panel stack, `panelForEscape`, and `useFloatingPanelEscape` (see Escape below). The stack must stay a single module instance.
- `useDocumentDragGesture.ts` — the document `mousemove`/`mouseup` listener lifecycle for one pointer gesture (start/stop, detached on mouseup and unmount; optional `onEnd` sees the releasing mouseup).
- `usePanelDragResize.ts` — `usePanelDrag` (titlebar, honours `.fp-no-drag`, clamped to the viewport; a pointer past the window's edge arms a pop-out, released there it opens one at the pointer) and `usePanelResize` (bottom-right grip, bounded by `minSize` and the viewport), both on `useDocumentDragGesture`.
- Maximize/restore (OS-window style): double-clicking the titlebar (or the top-right maximize icon next to Close) fills the window; toggling back restores the exact prior `pos`/`size` (left untouched while maximized). Drag/resize are disabled while maximized. Titlebar controls carry `.fp-no-drag` so a double-click on the search box / buttons never maximizes.
- Escape: several panels can be open at once (no backdrop), so `useFloatingPanelEscape` keeps an open-order stack and only ONE panel handles a given Escape — the panel the key was pressed in, or the most recently opened one when nothing is focused (target = body). Focus in a control outside every panel closes none. Inner layers (`Modal`, task overlays via `shared/useEscapeToClose`, `SettingsInfo`) stop propagation in the capture phase first.
- Non-modal: the panel is `role="dialog"` WITHOUT `aria-modal`, and uses `useFocusTrap(open, { trapTab: false })` — focus moves in on open (unless a child already has it) and returns to the opener on close, but Tab is never wrapped and the panel never joins the modal trap stack. Panels have no backdrop and sit side by side, so the old trap pulled Tab from older panels (and from the page) into the newest one. Real modals (`Modal`, confirms, folder picker) keep their trap. Pinned by `__tests__/focusTrapNonModal.test.ts`.

## Pop-out (the panel in its own OS window)

- The titlebar's pop-out button (or a titlebar drag released past the main window's edge — the mousedown is the user gesture `window.open` needs) moves the panel into a popup of `frontend/public/popout.html`, a same-origin blank page: the initial about:blank renders in quirks mode, and `document.write` would give the popup the app's URL. Popped out, drag/resize/maximize are off and CSS (`.floating-panel.popped-out`) fills the window.
- `usePopout.ts` owns one popup's life: open (blocked → an `ErrorToast` in the panel, which stays put), wait for load, mirror styles (`popoutStyles.ts`: every main-head `<style>` / stylesheet `<link>` in cascade order, `<html>` attributes, `<body>` class / data-*, kept in step by a MutationObserver — Vite HMR rewrites style text), register it (`popoutRegistry.ts`), persist placement under `lattice.<thing>.popout` (`popoutGeometry.ts`, screen coordinates, sampled each second: a move fires no event). The popup's title is the panel title's text.
- No white or unstyled flash: `popout.html` and the window's initial about:blank paint `--bg-elev` dark before any stylesheet exists, and styles are mirrored BEFORE the panel moves in — it moves only once mirrored `<link>`s have loaded (`whenStylesheetsLoaded`; dev styles are inline and ready at once).
- **State survives because nothing remounts:** the panel portals into ONE host `<div>` for its whole life, and pop-out / return MOVE that element between documents (`PanelHostMount`, rendered before the portal so content is attached before children's layout effects). Never portal a panel into a per-window container — React would remount the subtree and drop every child's state.
- "Return to main window" puts the panel back in the main window, still open; closing the popup window (OS close, F5 in it) closes the panel through its own `onClose` (moved back first, so a panel that confirms unsaved changes asks in the main window); closing the panel closes its popup; the main window's `pagehide` closes every popup (they would be orphaned). A reopened panel starts in the main window.
- Content reads its window via `hooks/usePanelDocument` (`PanelHostProvider` is set here): listeners, portals, focus, the clipboard (an unfocused window's rejects), timers / `ResizeObserver` / rAF that must run while the main window is minimised (throttled), and no `instanceof Element` across realms (`isElementLike`). The Escape stacks (`panelEscapeStack.ts`, `shared/useEscapeToClose`) are per window; a move re-targets the listener but keeps the layer's place in the open order.
- Polling above a panel (board / workflow controllers, StuckPill, Security) pauses only when EVERY Lattice window is hidden: `isLatticeHidden()` / `onLatticeVisibilityChange()`, never `document.visibilityState` alone. App-root dialogs (`ConfirmDialog`, Git Setup) open in the window the user last pressed in (`interactionDocument()`) and move to the main window if that popup closes first.
- No panel mounts xterm or WebGL today (Fleet's terminal viewer is text); one that did would need per-document handling. Document Picture-in-Picture (Chromium-only, one window at a time) is a possible future host.
- Tests: `__tests__/popoutStyles`, `popoutGeometry`, `popoutRegistry`, `panelDocument`; e2e `e2e/popout.spec.ts`.
