Triage the Opengrep static-analysis findings for this project into tasks on the Lattice board for this active project. Lattice ran an Opengrep scan just before this step; the digest is in `OPENGREP_FINDINGS.md` in this directory (the "Tool reports" section above names it). Read it in full before doing anything else. Do not fix anything yourself and do not commit — the board entries are your output.

Group the findings by rule and by the subsystem they touch. For each group decide whether it is a real problem, a defensible pattern that needs no change, or rule noise for this codebase — say which, briefly, for every group. Read the affected code where the digest's snippet is not enough to judge.

File ONE task per group that deserves work. Each task must give: the rule id and why it matters (the CWE or category), every affected `file:line`, the fix approach the implementing agent should take (the safe API, the missing check, the validation to add), and one line `opengrep:<fp>` per finding using the short fingerprint from the digest, so the task can be matched back to the finding later. Before filing, search the board for each fingerprint and skip any finding that already has a task — open or done (a done task whose finding still shows means "won't fix", not "file again").

For rule groups that are pure noise in this project, do not file a task: add the rule ids (or, for a single misfiring match, the finding's fingerprint) to the project's Opengrep ignore list yourself with the `opengrep_ignore` tool — or `POST /api/opengrep/ignore` with `{"project": ..., "ruleIds": [...], "fingerprints": [...]}` when the tool is not available — and state in your wrap-up what you ignored and why. The ignore list is Lattice settings for this project, not a project file, so this is within the planning-step rules; a human can review or remove entries in Settings → Tools. If the digest says findings were cut for its byte budget or capped per file, use the `opengrep_findings` tool (or the API URL the digest gives) to read the rest before deciding. If the report says the scan could not run, say so and file nothing.
