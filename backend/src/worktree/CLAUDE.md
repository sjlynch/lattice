# backend/src/worktree

Git-worktree subsystem. Public surface is re-exported from `../worktree.ts` (the shim).

## Modules

- `exec.ts` — spawn helper with hard timeout. Worktree-side git invocations go through this directly; project-repo git calls go through `projectGit` (below).
- `projectGit.ts` — **`projectGit(repoRoot, args)`**: the only sanctioned way to run git against the user's project repo. Asserts `<repoRoot>/.git` exists, then dispatches argv validation against the project-git policy modules before git runs. `assertAllowedProjectGitArgs` remains the public/unit-tested policy entry point.
- `projectGit/policy.ts` + `projectGit/validators/*.ts` — shared whitelist constants/utilities and one validator per mutating project-git subcommand group (`worktree`, `branch`, `merge`, `checkout`, `reset`, `rm`). The effective allow/deny policy is unchanged: reads, `add`/`commit`/`rm --cached`, `worktree add|remove|prune`, `branch -D lattice/*`, `merge --ff-only`, `checkout … -- <explicit paths>`, `reset … -- <paths>`, `bundle`; rejects `clean`, `stash`, `reset --hard`, `update-ref -d`, non-ff `merge`, `branch -D <non-lattice>`, `checkout <branch>`, `push`, leading `-C/-c`, …
- `gitBackup.ts` — `backupProjectGitBundle(repoRoot)`: `git bundle create ~/.lattice/git-backups/<hash>/<ts>.bundle --all`, keeps last 5. Called once per merge run (pre-flight). Recovery = `git fetch <bundle>`.
- `setup.ts` — `setupTaskWorktree(repoPath, task, backendOrigin, harness)` orchestrates the split setup phases: `setupProject.ts` resolves the repo root and runs project hygiene in the required order (`ensureLatticeGitignore` → `ensureLatticeRepoExclude` → `untrackOwnedFilesInRepo`), `setupCandidates.ts` builds the canonical/retry path+branch sequence under **`~/.lattice/worktrees/<projectHash>/<slug>-<id>`**, `setupAdd.ts` reconciles stale state then runs `git worktree add` with the unchanged retry warnings/fallback behavior, and `setupFiles.ts` writes `LATTICE_TASK.md`, the always-installed Claude Stop hook, optional Pi completion extension, and worktree-local excludes. `setup.ts` stays the public facade and keeps the existing re-exports.
- `reconcile.ts` — `reconcileStaleState(repoRoot, branch, worktreePath)`: clear a leftover (path, branch) pair from a prior abandoned run so `git worktree add -b` won't collide ("Run" = fresh start). Holds `tryRmWithRetries` (the one remaining recursive `fs.rm`, scoped to `~/.lattice/worktrees/<hash>/…` — guarded by `assertNotReparsePoint` + `pruneReparsePointsUnder`) and `MAX_PATH_RETRY_SUFFIXES` / `RM_RETRY_DELAYS_MS`.
- `projectGuards.ts` + `projectGuards/` — stable facade plus focused guard modules: `gitignore.ts` owns repo `.gitignore` management, `repoExclude.ts` owns `.git/info/exclude`, `verify.ts` probes the essential exclusions, and `untrack.ts` removes Lattice-owned files from the index. Behavior is intentionally unchanged: project-repo git goes through `projectGit`, safety comments stay near the code, and no recursive deletion belongs here.
- `stopHook.ts` — worktree-local Stop-hook/Pi-completion/exclude installers. Wraps the top-level `claudeStopHook.ts` renderer so task worktrees and workflow steps (which call `claudeStopHook.ts` directly) keep byte-identical Claude hook JSON.
- `commands.ts` — pure command-string builders (claude/pi/codex, run/resume/conflict/stash). No I/O.
- `instructions.ts` + `instructions/` — markdown writers for `LATTICE_TASK.md`, `MERGE_INSTRUCTIONS.md`, `STASH_CONFLICT_*.md`. Each prepends an env-notes blockquote (from `envDetect.ts`) when the project uses a detected package manager. `instructions.ts` is the public re-export shim; the actual rendering is split across `instructions/taskPrompt.ts` (`renderTaskMarkdown`), `instructions/mergePrompt.ts` (`writeMergeInstructions`), `instructions/stashPrompt.ts` (`writeStashResolveInstructions` + `writeRunStashResolveInstructions`), `instructions/stopHookRepair.ts` (`ensureValidStopHook` — repairs a broken `.claude/settings.local.json` before a resolver Claude spawns), and `instructions/shared.ts` (common markdown snippets + `renderEnvBlockFor`).
- `envDetect.ts` + `envDetect/` — `detectProjectEnvironments(repoRoot)`: root-only probe for package-manager environments whose heavy gitignored dir (`node_modules`, `.venv`, `target`, …) won't be in a fresh worktree — reported only when the marker file exists, the heavy dir is installed in the main checkout, and it's untracked by git. `envDetect/detectors.ts` holds the node/python/rust/ruby/php/go/maven/gradle/dotnet marker + manager rules; `envDetect/notes.ts` owns `defaultEnvNote` (the built-in "you're in a throwaway worktree, don't reinstall unless the task needs it" text) and markdown blockquote rendering. `describeProjectEnvs` layers `UserSettings.worktreeEnvNotes` overrides on top (empty string ⇒ suppressed) for the settings dialog; `resolveEnvNotesForInstructions` returns the effective notes the instruction writers inject.
- `state.ts` — read-only checks: `isMidMerge`, `worktreeExists`, `gitDirExists`/`assertGitDirIntact`, branch reachability + commit counts, `parseWorktreesPorcelain` (tested). Read-only ⇒ plain `exec`, not `projectGit`.
- `snapshot.ts` + `snapshot/` — copy-based working-tree snapshot (replaces `git stash --include-untracked`). `snapshot.ts` is the stable facade; `snapshot/manifest.ts` owns handle/manifest constants + safe read/write helpers, `capture.ts` is split into auditable phases (status parse → repo-containment filter → snapshot dir → copy accounting → manifest → reset/delete only copied paths), `restore.ts` copies them back (last-writer-wins, never deletes), and `recovery.ts` boot-restores orphans. Paths are validated to stay inside the repo; recovery refuses tampered project hashes.
- `merge.ts` — `mergeWorktreeInRepo` runs `git merge` *inside the worktree* (so main's vite-watched files never see conflict markers); `fastForwardMain` snapshots the tree, FF's main via `projectGit … merge --ff-only`, restores the snapshot.
- `stash.ts` — legacy name; delegates entirely to `snapshot.ts`. Keeps `RUN_STASH_LABEL` + `assertSafeForStash` (self-heals `.git/info/exclude`, verifies `.lattice/`+`node_modules/` are ignored).
- `finalize.ts` — `finalizeMergedTask`: FF main, write `qa` crash-safe, schedule background cleanup. Per-project promise queue serializes finalizes.
- `cleanup.ts` — `cleanupWorktreeForTask`: kill PTYs by cwd (Windows holds dir locks) → `pruneReparsePointsUnder` (strip junctions/symlinks *inside* the worktree — see `reparsePoints.ts`) → `git worktree remove --force` (via `projectGit`, with timeout) → `git branch -D` (only `lattice/*`) → `git worktree prune`. **No raw `fs.rm` fallback** — if `git worktree remove` fails, the dir is left in place (inert, since it's outside the project) and the boot-time `sweepOrphanedWorktrees` retries it. Pure orchestration; the safety bounds + reparse-point traversal live in their own modules below.
- `cleanupSafety.ts` — path-safety bounds for any worktree teardown. `isUnderManagedWorktreesDir(path, repo)` decides whether a path is under `~/.lattice/worktrees/<hash>/` or the legacy in-project location (used by the boot sweep + as a sanity bound); `assertSafeWorktreePath` throws on an empty/repo-root/out-of-bounds worktree path before any git call; `assertNotReparsePoint` refuses an `fs.rm` whose lstat is a symlink or whose `realpath` resolves elsewhere (catches Windows junctions / mount points / 8.3 aliases). Used by `cleanup.ts` and by `reconcile.ts`'s `tryRmWithRetries`.
- `reparsePoints.ts` — `pruneReparsePointsUnder(dir)`: removes just the *link* for every reparse point under `dir` (never follows it, never touches its target; skips ordinary `node_modules` package subtrees) — without it, an in-worktree `npm install` of a `file:..` self-dep leaves `node_modules/<pkg>` as a junction back to the worktree root, and `git worktree remove` then fails on Windows with `failed to delete …: Function not implemented` (git's recursion walks the loop past MAX_PATH), orphaning the worktree forever (the boot sweep can't converge either). Called from `cleanup.ts` before the `git worktree remove`, and from `reconcile.ts`'s `tryRmWithRetries` before any recursive `fs.rm`.

## Defence in depth against `.git` deletion

The only mechanism that has ever deleted `.git` is a recursive filesystem delete reaching it (directly via `fs.rm`, or via a lost `git stash --include-untracked`). Layers, outermost first:

1. **Worktrees live outside the project** (`~/.lattice/worktrees/<hash>/`) — no worktree-path `fs.rm` Lattice issues can be an ancestor/descendant of `<repo>/.git`.
2. **`projectGit` capability whitelist** — a destructive git subcommand against the project repo throws before running.
3. **No `fs.rm` fallback in cleanup** — recursive worktree removal is delegated to `git worktree remove`, which knows the exact dir and won't follow symlinks out.
4. **`pruneReparsePointsUnder` before any recursive removal** — strips junctions/symlinks inside the worktree first, so neither git's recursion nor the reconcile-path `fs.rm` can walk a reparse-point loop (an in-worktree `npm install` of a `file:..` self-dep is the realistic source).
5. **Copy-based snapshots** — no `git stash`; a crash leaves a recoverable snapshot dir, never a silent delete.
6. **Run circuit breaker** (mergeRuns.ts) — `.git`-exists + HEAD-only-moved-forward check after every task; a violation halts the whole run.
7. **`git bundle --all` pre-run backup** — last-resort full-history recovery.
8. Plus: `assertNotReparsePoint` on the remaining fs.rm sites, snapshot-manifest path validation, cross-process project run lock. (`backend/`'s own `package.json`/`frontend/package.json` no longer carry a `lattice: file:..` self-dep — that was what made `npm install` mint the junction in the first place.)

## Critical ordering (finalize.ts)

1. `fastForwardMain` (snapshots dirty tree, FFs, restores snapshot). Returns `{status:'error'}` or `{status:'clean'}` — never a conflict.
2. `updateTaskCrashSafe({status: 'qa', ...})` — disk first, cache second.
3. `scheduleWorktreeCleanup` — runs in a per-project queue **after** finalize returns. Stuck cleanup never blocks the run worker; the boot sweep mops up anything it leaves.
