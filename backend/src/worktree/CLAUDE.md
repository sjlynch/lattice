# backend/src/worktree

Git-worktree subsystem. Public surface is re-exported from `../worktree.ts` (the shim).
**Read the Invariants section before touching the merge / cleanup pipeline** — every
rule there traces to a real incident. Sub-docs: `merge/CLAUDE.md`, `snapshot/CLAUDE.md`,
`projectGit/CLAUDE.md`, `projectGuards/CLAUDE.md`, `instructions/CLAUDE.md`.

## Invariants

### Defence in depth against `.git` deletion

The only mechanism that has ever deleted `.git` is a recursive filesystem delete reaching it (directly via `fs.rm`, or via a lost `git stash --include-untracked`). Layers, outermost first:

1. **Worktrees live outside the project** (`~/.lattice/worktrees/<hash>/`) — no worktree-path `fs.rm` Lattice issues can be an ancestor/descendant of `<repo>/.git`.
2. **`projectGit` capability whitelist** — a destructive git subcommand against the project repo throws before running.
3. **No `fs.rm` fallback in cleanup** — recursive worktree removal is delegated to `git worktree remove`, which knows the exact dir and won't follow symlinks out. No global `git worktree prune` either.
4. **`pruneReparsePointsUnder` before any recursive removal** — strips junctions/symlinks inside the worktree first, so neither git's recursion nor the reconcile-path `fs.rm` can walk a reparse-point loop (an in-worktree `npm install` of a `file:..` self-dep is the realistic source).
5. **Copy-based snapshots** — no `git stash`; a crash leaves a recoverable snapshot dir, never a silent delete. The same copy routine archives a discarded worktree's uncommitted edits before reconcile / the boot sweep / cleanup force-removes it (`discardArchive.ts`); no archive, no removal.
6. **Run circuit breaker** (`mergeRuns.ts`, `mergeRuns/repoIntegrity.ts`) — `.git`-exists + HEAD-only-moved-forward check after every task; a violation halts the whole run.
7. **`git bundle --all` pre-run backup** — last-resort full-history recovery.
8. Plus: `assertNotReparsePoint` on the remaining `fs.rm` sites, snapshot-manifest path validation, cross-process project run lock. (`backend/`'s own `package.json` / `frontend/package.json` no longer carry a `lattice: file:..` self-dep — that was what made `npm install` mint the junction in the first place.)

### exec / projectGit

- `exec` decodes output via `setEncoding('utf8')` (a multi-byte path split across two pipe reads must not become U+FFFD); a timeout resolves within `EXEC_KILL_GRACE_MS` of the kill even if a grandchild (git hook, credential helper) still holds the stdio pipes; a nonexistent `cwd` REJECTS (`spawn git ENOENT`) rather than returning a non-zero code; an optional `env` is merged over `process.env` for that child only.
- **All project-repo git goes through `projectGit`**; worktree-side git and the read-only `state.ts` helpers use plain `exec`. `projectGit` asserts `<repoRoot>/.git` exists, then validates argv before git runs.
- Policy (detail: `projectGit/CLAUDE.md`): allows reads, `fetch`, `add`/`commit`/`rm --cached`, any `worktree` op (`add -b/-B` only for `lattice/*`), `branch -d/-D/-f` only on `lattice/*`, `merge-file` only as `-p` (stdout, no `--object-id`), `merge --ff-only` (not combined with `--no-ff`/`--ff`/`--squash`/`--no-commit`), `checkout … -- <explicit paths>` (permits `:(literal)<real path>` for snapshot restore; rejects other magic and empty/whole-tree paths, including literal suffixes), read-only `symbolic-ref` (no `-d`), `reset … -- <paths>`, `bundle`, exactly `gc --auto [--quiet]`, `count-objects`. Rejects the rest (`clean`, `stash`, `reset --hard`, `update-ref -d`, `checkout <branch>`, `push`, leading `-C/-c`, …)
- `projectGit`'s `env` option allowlists only `GIT_LFS_SKIP_SMUDGE` (`assertAllowedProjectGitEnv`) — `GIT_DIR` & co would bypass the argv whitelist.

### Stale locks

- `staleGitLocks.ts` removes `index.lock`, `HEAD.lock`, `ORIG_HEAD.lock`, `packed-refs.lock`, the current branch's `<ref>.lock` (one abandoned `index.lock` from a disk-full crash failed all 25 fast-forwards of a run, 2026-09-23) **only when** older than 10 min AND no running `git`/`git-*` process started before it was written (the holder must predate its lock; an unreadable start time or a failed listing counts as a possible holder). Single-file `unlink`, never recursive. Called before every fast-forward (private `merge/fastForward.ts` `prepareFastForward`; `fastForwardMain` also retries an FF that hit a lock with 2/5/10 s back-off) and in the merge-run preflight (also before `projectInit` finishes an unborn repo); a lock still present after that halts the run once (`mergeRuns/repoIntegrity.ts`) instead of erroring every remaining task.
- `staleInitLock.ts`: `git worktree add` locks the registration with reason `initializing` until checkout finishes; a backend killed mid-checkout leaves it forever and cleanup / reconcile / the boot sweep all honour locks, stranding a multi-GB half-checkout. The lock is cleared (`worktree unlock`) **only when** the reason is exactly `initializing`, the checkout is under a managed dir, and the admin dir's `locked` file is > 10 min old; those three callers invoke it before their lock check. `parseWorktreesPorcelain` keeps `lockReason` for this.

### Disk space, LFS, gc

- **Checkout gate**: ≤ 2 concurrent `git worktree add`s machine-wide, FIFO (parallel large-repo checkouts + LFS smudge thrashed the disk and, with on-access AV, pinned the CPU). `setup.ts` takes the disk reservation *inside* the slot so waiting setups hold none. Every `worktree add` (setup + merge preflight's re-create) is bounded by `WORKTREE_ADD_TIMEOUT_MS` (30 min, `setupAdd.ts`) — a hung `post-checkout` hook / LFS smudge / credential prompt used to hold a slot forever. A timed-out setup add is cleaned via `reconcileStaleState` and throws (no retry on other suffixes); a timed-out re-create removes its partial checkout (the branch is kept).
- **Disk guard** (right before every `git worktree add`, setup + re-create): admit only if `free − in-flight reservations − estimate ≥ minFreeDiskGb` (default 10), else throw `SpawnDiskSpaceError` — a spawn-queue **deferral**, never a failure (`../spawnQueue/CLAUDE.md`). Estimate = allocated size of every `git ls-files` path in the main checkout, cached 10 min, raised to the largest measured fresh worktree (`recordWorktreeCheckoutSize`). Cache and observation are keyed by repo **and LFS mode** (pointer mode counts each LFS path as `POINTER_FILE_BYTES`, 1 KB; one mode's observation never raises the other's estimate). Unmeasurable → admit (never block on its own blind spot). Tests: `__tests__/diskSpaceGuard.test.ts`, `__tests__/taskWorktreeLfsPointers.test.ts`.
- **LFS pointer mode** (`UserSettings.taskWorktreeLfsContent`, absent = `'pointers'`, `'full'` restores smudging; 22 multi-GB Ready-to-Merge worktrees filled the disk, 2026-09-23). `GIT_LFS_SKIP_SMUDGE=1` goes to every git that checks files out INTO a task worktree: the `worktree add` (`setupAdd.ts`, the re-create via `taskWorktreeCheckoutEnv`), the worktree-side `git merge` (`merge/runWorktreeMerge.ts`) and `git merge --abort` (`state.ts`) — those two resolve the project from the worktree's common git dir and read the setting **at merge time** (`worktreeCheckoutEnv`; a mode mismatch just affects the few LFS files main changed, harmless) — and the task / worktree-resolver pty (`terminalServerClient/createSession.ts`, via the `managedMcpEnv` wire field so an older terminal-server applies it too). Pointer stubs are what LFS's clean filter yields, so `git status` stays clean and commits/merges carry pointers. **Main's fast-forward runs with the normal env** and smudges real content from the shared LFS store. `lfsMode.ts` must stay free of `projectGit` (so `state.ts` imports it without a cycle). The `git lfs pull --include="<path>"` note (read-only `ls-files -- ':(attr:filter=lfs)'`, appended to env notes → `{{env_notes_block}}`) renders only in pointer mode on a repo with LFS files. Test: `__tests__/taskWorktreeLfsPointers.test.ts` (skipped without `git lfs`).
- **Merge disk floor**: a merge refuses to start under `MERGE_MIN_FREE_BYTES` (1 GB) — a floor, not the reserve, since merging is what frees space. See also merge-residue below.
- **No git auto-gc from Lattice**: `exec` gives every git child `gc.auto=0` + `maintenance.auto=false` via `GIT_CONFIG_COUNT/KEY_n/VALUE_n` (appending to any existing count); agent ptys get the same env (`terminalServerClient/createSession.ts`). Why: 2026-09-24 auto-gc after each merge repacked a 4.2 GB repo repeatedly; on Windows the mapped old packs couldn't be deleted — 80 GB of copies in minutes. `runRepoMaintenance` (a minute after each merge run, single-flight, skipped while the project merges) sweeps debris — `tmp_*` older than 6 h and `pack-*.pack` whose `.idx` is gone; never a `.keep` pack, never while a fresh `gc.pid` exists, single-file unlinks only — then runs `gc --auto --quiet` in the foreground (`exec` `autoGc: 'foreground'`) only when free space covers another full pack copy above the reserve, **holding the project run lock (non-lendable, `repo-maintenance`) across the gc**. `startMergeRun` refuses while `isRepoMaintenanceRunning` with a typed `RepoMaintenanceBusyError`; workflow control steps `waitForRepoMaintenance` first (`__tests__/repoMaintenanceMergeGate.test.ts`). Callbacks that restart a run for the remaining Ready-to-Merge tasks (`/stash-resolved`, the resolver finalize, the mid-run restart) go through `startMergeRunAfterMaintenance`, which waits out the gc and retries — they used to swallow the refusal as "a run is already active", stranding those tasks (`__tests__/stashResolvedAfterMaintenance.test.ts`).
- **Bundle backup retention**: bounded by count (5) **and** bytes (8 GB/project, newest always kept); old bundles pruned *before* the new one is written; skipped when the volume can't hold it above `minFreeDiskGb`; a bundle under 10 min old is reused (a workflow Merge step runs merge runs back to back).
- **Bundle leftovers**: `git bundle create` writes through `<ts>.bundle.lock`, which a timeout kill or a backend death leaves behind (on Windows an orphaned `pack-objects` can keep filling it): a failed bundle removes its `.lock` too, each backup first sweeps non-`.bundle` leftovers untouched for longer than any bundle may run (`LEFTOVER_STALE_MS`), and any leftover still on disk counts against the byte budget. The timeout scales with the expected bundle size (60 s + 60 s/GiB, cap 20 min) — a flat 60 s killed every backup of a multi-GB repo. Covered by `__tests__/gitBackupLeftovers.test.ts`.

### Teardown: reconcile, cleanup, archive

- **Discard archive before any force-removal.** Reconcile, the boot orphan sweep and `cleanupWorktreeForTask` (post-merge finalize, task delete, failed-run teardown) archive a worktree's uncommitted edits first (`git worktree remove --force` would silently drop them) into `~/.lattice/snapshots/<projectHash>/<ts>-discarded-worktree-<slug>-XXXX/files/`, reusing the snapshot machinery with the WORKTREE as copy source. Lattice-managed files (`LATTICE_EXCLUDE_PATTERNS` untracked, `LATTICE_OWNED_FILE_PATHS` tracked, `.lattice/`) are skipped; the worktree is never mutated. Returns `absent`/`clean`/`archived`/`failed`; on `failed` (git can't vouch for the checkout, a path dropped by containment, any copy failure, manifest write) **callers MUST keep the worktree**. Manifest is `_lattice-discarded-worktree.json`, deliberately NOT `_lattice-snapshot.json`, so `recoverPendingSnapshots` (and older backends) never auto-restore it into the project. Retention: newest `DISCARDED_WORKTREE_ARCHIVE_KEEP` (20) per project, but never one younger than `DISCARDED_WORKTREE_ARCHIVE_MIN_AGE_MS` (7 days — a boot sweep over hundreds of orphans would otherwise delete archives seconds after their only-copy checkout); prune is guarded (direct child of the project's snapshot dir, `assertNotReparsePoint` + `pruneReparsePointsUnder` first); pending merge snapshots are never candidates. Test: `__tests__/worktreeDiscardArchive.test.ts`.
- **Reconcile** frees only an exact managed fresh-run candidate: checks NUL-delimited git registrations, branch ownership, explicit locks, nested checkouts and physical path before mutating; **refuses when the candidate branch has unmerged commits** (`rev-list --count HEAD..<branch>` > 0 — a task moved back to Open keeps its branch and a fresh ▶ Run would otherwise `branch -D` the only copy; setup falls through to the `-rN` suffix, and the boot sweep applies the same guard); rechecks after waiting for PTY shutdown; a failed archive keeps the checkout (setup takes `-rN`); preserves other/main/moved/locked registrations and stops on git removal failure. Exact git removal handles a missing directory without global prune. Its `fsRmWithRetries` path is limited to verified unregistered home-scoped strays without a `.git` marker, with `guardReparse: true`, and never follows a failed registered removal.
- **Cleanup** order: validate exact registration, expected branch/detached state, locks, physical path → kill PTYs by cwd → recheck registration → archive (`opts.skipArchive` only when the caller — the boot sweep — already archived) → strip internal reparse points → exact `git worktree remove --force` → verify no remaining checkout uses the branch → delete only `lattice/*`. `opts.keepBranchIfUnmerged` (task delete, `routes/tasks/crudDelete.ts`) KEEPS the branch when `rev-list --count HEAD..<branch>` > 0 **or cannot be determined** (fail safe), reported via `opts.onBranchKept({name, unmergedCommits})` while returning `true`; finalize doesn't set it (merged by construction). Returns `true` for completed/idempotent cleanup, `false` for a preserved/deferred checkout or branch. A failed `worktree remove` re-reads registrations: still registered → branch + registration kept together for the boot orphan sweep; registration already gone (Windows, a locked file stopped it part-way, `.git` gone too) → leftovers logged for the residue sweep (`recovery/worktreeResidueSweep.ts`) and the branch step runs (`keepBranchIfUnmerged` still applies), returning `true`. Missing dirs are unregistered through exact git removal; unregistered existing dirs, locked/moved/repurposed/nested checkouts and permission-unknown paths are preserved.
- `rmRetry.ts` is the single transient-error recursive-delete loop (reconcile + `homeScratch/cleanup.ts`): only EBUSY/EPERM/ENOTEMPTY are transient; the two callers' `delays` intentionally differ — **do NOT unify**; logs + returns `false` on final failure. `guardReparse: true` (reconcile) runs `assertNotReparsePoint` + `pruneReparsePointsUnder` inside the loop; home-scratch cleanup leaves it off because it runs those guards itself.
- `cleanupSafety.ts`: `isUnderManagedWorktreesDir` bounds a path to `~/.lattice/worktrees/<hash>/` or the legacy in-project location (boot sweep + sanity bound); `assertSafeWorktreePath` throws on an empty / repo-root / out-of-bounds path before any git call; `assertNotReparsePoint` refuses an `fs.rm` whose lstat is a symlink or whose `realpath` resolves elsewhere (junctions / mount points / 8.3 aliases). Used by `cleanup.ts`, `homeScratch/cleanup.ts`, and reconcile via `guardReparse`.
- `pruneReparsePointsUnder(dir)` removes just the *link* of every reparse point (never follows it, never touches its target; skips ordinary `node_modules` package subtrees). Without it a `file:..` self-dep junction makes `git worktree remove` fail on Windows (`Function not implemented`, recursion past MAX_PATH), orphaning the worktree forever. Called by `cleanup.ts` before `worktree remove` and by reconcile before any recursive `fs.rm`.
- `pathExistsStrict` is the one existence probe for teardown + the archive: `lstat` (never follows a link), `false` ONLY on `ENOENT`, every other error rethrown — a permission failure is unknown state, never absence. Don't swap in a look-alike `stat` / swallow-all helper.
- `isPathStrictlyInside` is case-folded on win32 (callers mix `os.homedir()`-derived and git-reported spellings; a mismatch once made `assertSafeWorktreePath` refuse every cleanup of that worktree).
- `finalizeQueues.ts` `scheduleWorktreeCleanup` runs cleanup on a *separate* sequential per-project queue (two `git worktree remove`s must not race on `.git/index.lock`), decoupled from finalize (a hung cleanup must not stall the run worker once the task is qa-on-disk); errors are swallowed; completed vs deferred cleanup is logged accurately (the boot sweep retries registered orphans).

### Merge + fast-forward

- `git merge` runs *inside the worktree* so main's vite-watched files never see conflict markers; main only ever moves by `projectGit … merge --ff-only`.
- Both `mergeWorktreeInRepo` and `fastForwardMain` refuse when the project checkout is on a **detached HEAD** (`merge/preflight.ts` `assertMainOnBranch`, read-only `symbolic-ref -q HEAD`): an FF there lands the tip on nothing `main` can see, and cleanup then deletes the `lattice/*` branch.
- `preflightWorktreeMerge` **re-creates a hand-deleted worktree directory** from its still-existing branch (`worktree remove --force` the stale registration → `worktree add <path> <branch>` → re-install Stop hook + excludes) instead of failing the task forever.
- **Disk-full hardening (2026-09-24)**: refuse under `MERGE_MIN_FREE_BYTES`; before `git merge`, `merge/mergeResidue.ts` `clearMergeBlockingChanges` copies any uncommitted change to a path main changed since the merge base (residue of a merge that died part-way, or an agent's never-committed edit) to the discarded-worktree archive and restores it to HEAD — git would otherwise refuse every later merge; after a merge that fails with no merge in progress, `restoreFailedMergeWrites` undoes exactly the paths that attempt wrote (dirty-now minus dirty-before).

### Lattice-owned files

- `managedFiles.ts` is the single source for owned / exclude / shelve lists. The three "which owned files are tracked?" sites (`projectGuards/untrack.ts`, `conflictResolve.ts` `resetOwnedFileLocalChanges`, `mergeOwnedFiles.ts` `untrackOwnedFilesPostMerge`) each issue ONE `git ls-files -z -- <all owned paths>` parsed by `trackedOwnedPaths` — not one spawn per path (~9 × ~20 ms on the critical path). Keep it that way when adding a site; shelve/restore do the same.
- **Shelve invariants** (2026-08-24: `.codex/hooks.json` committed on main errored two tasks out with `untracked working tree files would be overwritten by merge` — an abort *before* any conflict exists, so no resolver can recover it): the shelve list comes from the central `LATTICE_SHELVE_PATHS`, never a local array; shelving is **untracked-only** (renaming a *tracked* file aside reads as a deletion and git refuses the merge for the opposite reason). Restore favours Lattice for owned paths (per-worktree content) but keeps a tracked `.codex/hooks.json` the merge brought in (may be the repo's own). Shelve first recovers any `<f>.lattice-bak` a killed backend left (moved back when the original is absent, dropped when a re-created file supersedes it); `*.lattice-bak` is in `LATTICE_EXCLUDE_PATTERNS` so a resolver's `git add -A` never commits one.
- `stopHook.ts` keeps Claude hook JSON byte-identical between task worktrees and workflow steps (both render via `../claudeStopHook.ts`). `.codex/hooks.json` is written **`if-absent`** (a repo-tracked one must never be clobbered); it is excluded from `git status` via `LATTICE_EXCLUDE_PATTERNS` but deliberately OUT of the owned/auto-resolve set (an ambiguous file must not silently resolve to "ours"); it IS in `LATTICE_SHELVE_PATHS`. One exception to `if-absent`: a file `isLatticeGeneratedCodexHooks` recognises as Lattice's own is rewritten — once committed on main, every fresh worktree would check out a *different* task's `/complete` URL and report the wrong task finished.
- `conflictResolve.ts`: "resolve to ours" is always correct for Lattice-owned files (a conflicted `.claude/settings.local.json` breaks the resolver Claude's bootstrap before it reads its instructions).
- `repoExclude.ts` writes **always to the COMMON gitdir** (`git rev-parse --git-common-dir`) — `info/exclude` is shared by the main checkout and every linked worktree — and `ensureLatticeRepoExclude` writes the FULL managed set so an existing project self-heals on its next merge/stash/setup. No recursive deletion in `projectGuards/`.
- Setup hygiene order is `ensureLatticeRepoExclude` → `untrackOwnedFilesInRepo`; the tracked `.gitignore` is never edited (only `git init` writes one).

### Snapshots

Full rules in `snapshot/CLAUDE.md` (capture order, scope, free-space refusal, argv chunking, ownership, restore policy). The ones stated only here:
- Paths are validated to stay inside the repo (`isPathInsideRepo`, which also refuses in-repo `.git/*` and `.lattice/*` so a corrupt/tampered manifest can't overwrite the gitdir); recovery refuses tampered project hashes.
- Boot recovery passes `guardStaleOverwrite`, so a *deferred* restore never clobbers a path the user changed since capture — it backs the snapshot copy up to a `.lattice-conflict` sibling instead. Immediate in-session restores overlay only verified clean tracked HEAD content, preserving newer dirty edits. A partial restore retains the snapshot and surfaces a run/finalize error.

### Finalize ordering (`finalize.ts` / `resyncFinalize.ts`)

Capture/finalize/restore share the project mutation owner; boot recovery acquires its own lock (supersedes historical snapshot-wins wording — see `snapshot/CLAUDE.md` and `../PROJECT_IDENTITY.md` for version checks and legacy snapshot identity).

1. Narrow `task.branch` + `task.worktreePath` before entering queued closures; return the existing missing-info error shape without touching git.
2. Inside the per-project finalize queue (`runSerializedFinalize` — two finalizes for one project must not interleave since FF moves main's HEAD; the slot is released in a `finally` so an early return/throw never jams it), assert the project `.git` is intact before any project-repo git.
3. FF main with `projectGit … merge --ff-only` only. On error, at most one in-queue `mergeWorktreeInRepo` re-sync against current main, then retry the FF once. A re-sync conflict is not a bare error: leave the worktree mid-merge, write `MERGE_INSTRUCTIONS.md` + set `task.conflict` (`mergeConflict.ts`), and return the merge-conflict outcome so a resolver can be spawned.
4. Stash/snapshot conflict outcomes keep their public shape (`stashConflict`, `resolveCommand`, `cwd`) and do not move the task to QA.
5. On success, `updateTaskCrashSafe({status: 'qa', ...})` before cleanup — disk first, cache second. Crash after the write ⇒ QA on disk; crash between FF and the write ⇒ startup recovery re-runs finalization. If the write FAILS (→ null: disk error or task gone), return an error and do **not** schedule cleanup — the task is still `ready_to_merge` and needs its worktree + branch for the retry (whose FF is then a no-op).
6. `scheduleWorktreeCleanup` runs **after** finalize returns (see Teardown). No raw `fs.rm` fallback.

`resyncWithMainAndFinalize` preserves caller hook ordering, short-circuits only when the caller opts into the ancestor check, writes first-pass conflict instructions before returning `merge-conflict`, and maps finalize retry conflicts / stash conflicts / errors back to the existing endpoint / merge-run outcome shapes.

## `state.ts` read-only query map

All read-only ⇒ plain `exec` (they must work against the project repo *or* a worktree; `projectGit` is project-repo-only). `parseWorktreesPorcelain` accepts NUL-delimited `worktree list --porcelain -z` (preserving unusual path bytes), legacy newline/CRLF output, and explicit lock metadata. Groups → functions → primary consumers:

- **Worktree existence & git-dir safety** — `worktreeExists` (`cleanup.ts`, `reconcile.ts`, `merge/preflight.ts`, `routes/tasks/resume{Route,Task}.ts`); `gitDirExists` (`merge/fastForward.ts`, `stash.ts`, `mergeRuns/preflight.ts` + the `mergeRuns/repoIntegrity.ts` circuit breaker); `assertGitDirIntact` (loud-fail wrapper at the top of every project-repo mutation — `projectGit.ts`, `finalize.ts`, `cleanup.ts`, `projectGuards/untrack.ts`, `merge/preflight.ts`).
- **Porcelain parsing** — `parseWorktreesPorcelain` → `ParsedWorktree[]` (`recovery/worktreeSweep.ts`, `reconcile.ts`; tested in `__tests__/worktree.test.ts`).
- **Merge state & abort** — `isMidMerge` (MERGE_HEAD via the private `getWorktreeGitDir`, which reads a nonexistent directory as "no git-dir" ⇒ `false` instead of letting exec's ENOENT rejection crash the merge-run worker; `merge.ts`, `merge/preflight.ts`, `routes/tasks/finalizeResolved.ts`, `routes/tasks/hooks/mergeAborted.ts`, `routes/tasks/manualMergeService.ts`, `mergeRuns/flaggedConflict.ts`); `abortWorktreeMerge` (`git merge --abort`, safe only after `isMidMerge`; `mergeAborted.ts`, `merge/preflight.ts`).
- **Branch/commit reachability** — `checkBranchExists` (`recovery/index.ts`; **throws** on a non-zero git exit — only exit 0 with no match is a confirmed absence; reading a transient failure as "branch gone" once moved a task with unmerged commits to `qa` and let the next boot's sweep delete its branch); `countBetween` (`from..to` count that **throws** on git failure so a transient error never reads as `0`; `__tests__/execSignalKill.test.ts`); `branchCommitCount` (`HEAD..branch`; the `/complete` Stop hook, `recovery/inProgressSweep/eligibility.ts`, `merge/branchState.ts`); `branchIsAncestorOfHead` (`merge/branchState.ts`); `mainIsAncestorOfWorktree` (FF without re-merge; `resyncFinalize.ts`, `mergeRuns/flaggedConflict.ts`).
- **Conflict-file listing** — `listConflictedFiles` (`git diff --name-only -z --diff-filter=U`; `-z` so a non-ASCII path isn't C-quoted into a non-path; `mergeRuns/resolverSpawn/spawn.ts`, `conflictResolve.ts`). Last function in the file — easy to miss.
