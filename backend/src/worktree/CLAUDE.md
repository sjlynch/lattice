# backend/src/worktree

Git-worktree subsystem. Public surface is re-exported from `../worktree.ts` (the shim).

## Modules

- `exec.ts` — spawn helper with hard timeout. Worktree-side git invocations go through this directly; project-repo git calls go through `projectGit` (below).
- `projectGit.ts` — **`projectGit(repoRoot, args)`**: the only sanctioned way to run git against the user's project repo. Asserts `<repoRoot>/.git` exists, then dispatches argv validation against the project-git policy modules before git runs. `assertAllowedProjectGitArgs` remains the public/unit-tested policy entry point.
- `projectGit/policy.ts` + `projectGit/validators/*.ts` — shared whitelist constants/utilities and one validator per mutating project-git subcommand group (`worktree`, `branch`, `merge`, `checkout`, `reset`, `rm`). The effective allow/deny policy is unchanged: reads, `add`/`commit`/`rm --cached`, `worktree add|remove|prune`, `branch -D lattice/*`, `merge --ff-only`, `checkout … -- <explicit paths>`, `reset … -- <paths>`, `bundle`; rejects `clean`, `stash`, `reset --hard`, `update-ref -d`, non-ff `merge`, `branch -D <non-lattice>`, `checkout <branch>`, `push`, leading `-C/-c`, …
- `gitBackup.ts` — `backupProjectGitBundle(repoRoot)`: `git bundle create ~/.lattice/git-backups/<hash>/<ts>.bundle --all`, keeps last 5. Called once per merge run (pre-flight). Recovery = `git fetch <bundle>`.
- `setup.ts` — `setupTaskWorktree(repoPath, task, backendOrigin, harness)` orchestrates the split setup phases: `setupProject.ts` resolves the repo root and runs project hygiene in the required order (`ensureLatticeGitignore` → `ensureLatticeRepoExclude` → `untrackOwnedFilesInRepo`), `setupCandidates.ts` builds the canonical/retry path+branch sequence under **`~/.lattice/worktrees/<projectHash>/<slug>-<id>`**, `setupAdd.ts` reconciles stale state then runs `git worktree add` with the unchanged retry warnings/fallback behavior, and `setupFiles.ts` writes `LATTICE_TASK.md`, the always-installed Claude Stop hook, optional Pi completion extension, and worktree-local excludes. `setup.ts` stays the public facade and keeps the existing re-exports.
- `reconcile.ts` — `reconcileStaleState(repoRoot, branch, worktreePath)`: clear a leftover (path, branch) pair from a prior abandoned run so `git worktree add -b` won't collide ("Run" = fresh start). The one remaining recursive `fs.rm` (scoped to `~/.lattice/worktrees/<hash>/…`) is delegated to `fsRmWithRetries` (`rmRetry.ts`) with `guardReparse: true`, so it still runs `assertNotReparsePoint` + `pruneReparsePointsUnder` before the delete. Holds `MAX_PATH_RETRY_SUFFIXES` and its own `RM_RETRY_DELAYS_MS` (passed to the shared helper).
- `rmRetry.ts` — `fsRmWithRetries(target, { delays, logPrefix, guardReparse })`: the single transient-error recursive-delete retry loop, shared by `reconcile.ts` and `pushRuns/cleanup.ts` (which previously each had a near-identical copy). Treats only EBUSY/EPERM/ENOTEMPTY as transient, sleeps the caller-supplied `delays` between attempts (the two callers intentionally use different values — do NOT unify), logs + returns `false` on final failure. `guardReparse: true` (reconcile) runs `assertNotReparsePoint` + `pruneReparsePointsUnder` inside the loop first; pushRuns leaves it off because it runs those guards in its own orchestration.
- `projectGuards.ts` + `projectGuards/` — stable facade plus focused guard modules: `gitignore.ts` owns repo `.gitignore` management, `repoExclude.ts` owns `.git/info/exclude`, `verify.ts` probes the essential exclusions, and `untrack.ts` removes Lattice-owned files from the index. Behavior is intentionally unchanged: project-repo git goes through `projectGit`, safety comments stay near the code, and no recursive deletion belongs here.
- `stopHook.ts` — worktree-local Stop-hook/Pi-completion/exclude installers. Wraps the top-level `claudeStopHook.ts` renderer so task worktrees and workflow steps (which call `claudeStopHook.ts` directly) keep byte-identical Claude hook JSON.
- `commands.ts` — pure command-string builders (claude/pi/codex, run/resume/conflict/stash). No I/O.
- `instructions.ts` + `instructions/` — markdown writers for `LATTICE_TASK.md`, `MERGE_INSTRUCTIONS.md`, `STASH_CONFLICT_*.md` (see its `CLAUDE.md`). Each prepends an env-notes blockquote (from `envDetect.ts`) when the project uses a detected package manager. `instructions.ts` is the public re-export shim; the actual rendering is split across `instructions/taskPrompt.ts` (`renderTaskMarkdown`), `instructions/mergePrompt.ts` (`writeMergeInstructions`), `instructions/stashPrompt.ts` (`writeStashResolveInstructions` + `writeRunStashResolveInstructions`), `instructions/stopHookRepair.ts` (`ensureValidStopHook` — repairs a broken `.claude/settings.local.json` before a resolver Claude spawns), and `instructions/shared.ts` (common markdown snippets + `renderEnvBlockFor`).
- `envDetect.ts` + `envDetect/` — `detectProjectEnvironments(repoRoot)`: root-only probe for package-manager environments whose heavy gitignored dir (`node_modules`, `.venv`, `target`, …) won't be in a fresh worktree — reported only when the marker file exists, the heavy dir is installed in the main checkout, and it's untracked by git. `envDetect/detectors.ts` holds the node/python/rust/ruby/php/go/maven/gradle/dotnet marker + manager rules; `envDetect/notes.ts` owns `defaultEnvNote` (the built-in "you're in a throwaway worktree, don't reinstall unless the task needs it" text) and markdown blockquote rendering. `describeProjectEnvs` layers `UserSettings.worktreeEnvNotes` overrides on top (empty string ⇒ suppressed) for the settings dialog; `resolveEnvNotesForInstructions` returns the effective notes the instruction writers inject.
- `state.ts` — read-only checks: `isMidMerge`, `worktreeExists`, `gitDirExists`/`assertGitDirIntact`, branch reachability + commit counts, `parseWorktreesPorcelain` (tested). Read-only ⇒ plain `exec`, not `projectGit`.
- `snapshot.ts` + `snapshot/` — copy-based working-tree snapshot (replaces `git stash --include-untracked`). `snapshot.ts` is the stable facade; `snapshot/manifest.ts` owns handle/manifest constants + safe read/write helpers, `capture.ts` owns the snapshot types, dir creation, manifest write, cleanup-plan build, and the `snapshotWorkingTree` orchestrator that runs the auditable phases in order (status parse → repo-containment filter → snapshot dir → copy accounting → manifest → reset/delete only copied paths) — with `pathClassification.ts` (`parseStatus`/`filterSafeDirtyPaths`/`classifySafeDirtyPaths`/`logDroppedPaths`) and `copyAndCleanup.ts` (`copyDirtyPathsToSnapshot`/`logCopyFailures`/`resetTrackedSnapshotPaths`/`cleanupCapturedUntrackedPaths`) holding the two halves it calls (both re-exported from `capture.ts` so the public surface is unchanged), `restore.ts` copies them back (last-writer-wins, never deletes), and `recovery.ts` boot-restores orphans. Paths are validated to stay inside the repo; recovery refuses tampered project hashes.
- `merge.ts` — `mergeWorktreeInRepo` runs `git merge` *inside the worktree* (so main's vite-watched files never see conflict markers); `fastForwardMain` snapshots the tree, FF's main via `projectGit … merge --ff-only`, restores the snapshot.
- `stash.ts` — legacy name; delegates entirely to `snapshot.ts`. Keeps `RUN_STASH_LABEL` + `assertSafeForStash` (self-heals `.git/info/exclude`, verifies `.lattice/`+`node_modules/` are ignored).
- `finalize.ts` — `finalizeMergedTask`: the FF / re-sync / state-transition decision tree only (preflight narrow branch+worktree, assert project `.git`, FF main, at most one queued re-sync retry, write `qa` crash-safe, schedule background cleanup). Outcome handlers are intentionally narrow: retry re-sync conflicts write resolver instructions + flag the task; snapshot/stash conflicts keep their existing public shape; success writes QA before cleanup. The per-project serialization + cleanup-queueing plumbing lives in `finalizeQueues.ts`.
- `resyncFinalize.ts` — `resyncWithMainAndFinalize`: shared "merge main into the worktree, then finalize" orchestration. It preserves caller hook ordering, short-circuits only when the caller opts into the ancestor check, writes first-pass conflict instructions before returning a `merge-conflict`, and maps finalize retry conflicts/stash conflicts/errors back to the existing endpoint/merge-run outcome shapes.
- `finalizeQueues.ts` — the two per-project promise queues finalize.ts runs on, extracted so `finalizeMergedTask` stays focused on its decision tree. `runSerializedFinalize(projectPath, fn)` serializes finalize work per project (fastForwardMain moves main's HEAD, so two finalizes for the same project must not interleave; the slot is released in a `finally` so an early return/throw never jams the queue). `scheduleWorktreeCleanup(...)` enqueues background `cleanupWorktreeForTask` on a *separate* per-project queue (sequential so two `git worktree remove` calls don't race on `.git/index.lock`) but decoupled from finalize — a hung cleanup must not stall the run worker once the task is already qa-on-disk; errors are swallowed (the boot sweep retries an orphaned worktree).
- `cleanup.ts` — `cleanupWorktreeForTask`: kill PTYs by cwd (Windows holds dir locks) → `pruneReparsePointsUnder` (strip junctions/symlinks *inside* the worktree — see `reparsePoints.ts`) → `git worktree remove --force` (via `projectGit`, with timeout) → `git branch -D` (only `lattice/*`) → `git worktree prune`. **No raw `fs.rm` fallback** — if `git worktree remove` fails, the dir is left in place (inert, since it's outside the project) and the boot-time `sweepOrphanedWorktrees` retries it. Pure orchestration; the safety bounds + reparse-point traversal live in their own modules below.
- `cleanupSafety.ts` — path-safety bounds for any worktree teardown. `isUnderManagedWorktreesDir(path, repo)` decides whether a path is under `~/.lattice/worktrees/<hash>/` or the legacy in-project location (used by the boot sweep + as a sanity bound); `assertSafeWorktreePath` throws on an empty/repo-root/out-of-bounds worktree path before any git call; `assertNotReparsePoint` refuses an `fs.rm` whose lstat is a symlink or whose `realpath` resolves elsewhere (catches Windows junctions / mount points / 8.3 aliases). Used by `cleanup.ts`, by `pushRuns/cleanup.ts`, and (via `rmRetry.ts`'s `guardReparse`) by `reconcile.ts`'s recursive delete.
- `reparsePoints.ts` — `pruneReparsePointsUnder(dir)`: removes just the *link* for every reparse point under `dir` (never follows it, never touches its target; skips ordinary `node_modules` package subtrees) — without it, an in-worktree `npm install` of a `file:..` self-dep leaves `node_modules/<pkg>` as a junction back to the worktree root, and `git worktree remove` then fails on Windows with `failed to delete …: Function not implemented` (git's recursion walks the loop past MAX_PATH), orphaning the worktree forever (the boot sweep can't converge either). Called from `cleanup.ts` before the `git worktree remove`, and (via `rmRetry.ts`'s `guardReparse`) from `reconcile.ts`'s recursive delete before any recursive `fs.rm`.

## `state.ts` read-only query map

`state.ts` holds ~20 read-only git helpers whose grouping-by-concern is implicit in the file (and whose last function, `listConflictedFiles`, is easy to miss at end-of-file). All are read-only ⇒ they run on plain `exec` (they must work against either the project repo *or* a worktree; `projectGit` is project-repo-only). Groups → functions → primary consumers:

- **Worktree existence & git-dir safety** — `worktreeExists` (dir access probe; `cleanup.ts`, `reconcile.ts`, `merge/preflight.ts`, `routes/tasks/resume{Route,Task}.ts`); `gitDirExists` (`<repo>/.git` present?; `merge.ts`, `stash.ts`, `mergeRuns/preflight.ts` + `mergeRuns/repoIntegrity.ts` circuit breaker); `assertGitDirIntact` (the loud-fail wrapper run at the top of every project-repo mutation — `projectGit.ts`, `finalize.ts`, `cleanup.ts`, `projectGuards/untrack.ts`, `merge/preflight.ts`).
- **`git worktree list --porcelain` parsing** — `parseWorktreesPorcelain` → `ParsedWorktree[]` (`recovery/worktreeSweep.ts` orphan sweep, `reconcile.ts` stale-state clear; unit-tested in `__tests__/worktree.test.ts`).
- **Merge state & abort** — `isMidMerge` (MERGE_HEAD in the dir's git-dir, resolved via the private `getWorktreeGitDir`; `merge.ts`, `merge/preflight.ts`, `routes/tasks/finalizeResolved.ts`, `routes/tasks/hooks/mergeAborted.ts`, `manualMergeService.ts`, `mergeRuns/flaggedConflict.ts`); `abortWorktreeMerge` (`git merge --abort`, safe only after `isMidMerge`; `mergeAborted.ts`, `merge/preflight.ts`).
- **Branch/commit reachability** — `checkBranchExists` (`recovery/index.ts`); `countBetween` (base `from..to` range count that **throws** on a git failure so a transient error never reads as a genuine `0`; unit-tested in `__tests__/execSignalKill.test.ts`); `branchCommitCount` (`HEAD..branch` via `countBetween`; the `/complete` Stop hook, `recovery/inProgressSweep/eligibility.ts`, `merge/branchState.ts`); `branchIsAncestorOfHead` (already-merged?; `merge/branchState.ts`); `mainIsAncestorOfWorktree` (worktree already incorporates main ⇒ FF without re-merge; `resyncFinalize.ts`, `mergeRuns/flaggedConflict.ts`).
- **Conflict-file listing** — `listConflictedFiles` (`git diff --name-only --diff-filter=U`; `mergeRuns/resolverSpawn.ts`, `worktree/conflictResolve.ts`).

## Defence in depth against `.git` deletion

The only mechanism that has ever deleted `.git` is a recursive filesystem delete reaching it (directly via `fs.rm`, or via a lost `git stash --include-untracked`). Layers, outermost first:

1. **Worktrees live outside the project** (`~/.lattice/worktrees/<hash>/`) — no worktree-path `fs.rm` Lattice issues can be an ancestor/descendant of `<repo>/.git`.
2. **`projectGit` capability whitelist** — a destructive git subcommand against the project repo throws before running.
3. **No `fs.rm` fallback in cleanup** — recursive worktree removal is delegated to `git worktree remove`, which knows the exact dir and won't follow symlinks out.
4. **`pruneReparsePointsUnder` before any recursive removal** — strips junctions/symlinks inside the worktree first, so neither git's recursion nor the reconcile-path `fs.rm` can walk a reparse-point loop (an in-worktree `npm install` of a `file:..` self-dep is the realistic source).
5. **Copy-based snapshots** — no `git stash`; a crash leaves a recoverable snapshot dir, never a silent delete.
6. **Run circuit breaker** (mergeRuns.ts) — `.git`-exists + HEAD-only-moved-forward check after every task; a violation halts the whole run.
7. **`git bundle --all` pre-run backup** — last-resort full-history recovery.
8. Plus: `assertNotReparsePoint` on the remaining fs.rm sites, snapshot-manifest path validation, cross-process project run lock. (`backend/`'s own `package.json`/`frontend/package.json` no longer carry a `lattice: file:..` self-dep — that was what made `npm install` mint the junction in the first place.)

## Critical ordering (finalize.ts / resyncFinalize.ts)

1. Narrow `task.branch` + `task.worktreePath` before entering queued closures; return the existing missing-info error shape without touching git.
2. Inside the per-project finalize queue, assert the project `.git` is intact before any project-repo git command.
3. `fastForwardMain` main with `projectGit … merge --ff-only` only. If it errors, perform at most one in-queue `mergeWorktreeInRepo` re-sync against current main and retry the FF once. A re-sync conflict is not a bare error: leave the worktree mid-merge, write `MERGE_INSTRUCTIONS.md`, set `task.conflict`, and return the existing merge-conflict outcome so a resolver can be spawned.
4. Stash/snapshot conflict outcomes keep their public shape (`stashConflict`, `resolveCommand`, `cwd`) and do not mutate task status to QA.
5. On success, `updateTaskCrashSafe({status: 'qa', ...})` happens before cleanup — disk first, cache second. If the server crashes after this write, the task is QA on disk; if it crashes between FF and this write, startup recovery can re-run finalization.
6. `scheduleWorktreeCleanup` runs in a background per-project queue **after** finalize returns. Stuck cleanup never blocks the run worker; the boot sweep mops up anything it leaves. There is still no raw `fs.rm` fallback for worktree cleanup.
